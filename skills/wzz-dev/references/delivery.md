# 开发模板与预约示例

## 规格和技术设计

| 材料 | 可直接采用的字段 |
| --- | --- |
| PRD / 项目简报 | 用户与现状、要解决的问题、首版范围、暂缓范围、成功指标与数据来源、待决取舍 |
| spec.md | 用户场景、角色与权限、业务规则、AC 编号、前置条件、动作、可观察结果、边界样例、质量指标 |
| design.md | 关联 AC、技术栈及理由、已有能力、模块职责、数据流、失败处理、测试策略、上线兼容与恢复 |
| 接口契约 | 方法与路径、身份、请求字段与单位、响应与稳定错误码、成功与失败样例、兼容策略 |
| 表设计 | 表及主外键、字段类型、可空性、状态、约束、索引和查询入口；涉及并发时明确事务与原子性，既有数据变更时列出迁移顺序 |

## 任务卡

```text
任务 ID / 交付后用户能观察到的结果：
关联 AC / 规格和契约版本：
输入：设计章节、代码入口、现有测试、起始提交。
前置任务 / 当前状态 / 负责人：
允许修改的模块 / 共享文件写入人：
验证方法：场景、环境、命令及预期。
交付记录：实际提交、变化、执行结果、证据、未验证项。
```

## 集成与发布交接

| AC | 候选提交或制品标识 | 环境与用例 | 预期 | 实际 | 证据位置 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 填编号 | 填真实版本 | 填测试入口 | 从规格引用 | 执行后填写 | 日志或报告 | 通过／失败／未验证／阻塞 |

业务验收记录包含候选版本、验收人、场景与结果。发布单记录已验收制品、迁移和配置、观察指标、何时停放量及如何恢复。回退应用前检查它能否读取变更后的数据；已写入的数据需要单独核验。发布后按同一口径观察立项时约定的产品指标。

## 示例：会议室预约

**规格 AC-02。** 原本空闲的 A 室同时收到两名员工的有效请求，分别预约 10:00–11:00 和 10:30–11:30。两个请求处理完毕后恰好一个成功，另一个收到冲突提示，库中恰好一条有效预约。相邻的 11:00–12:00 可以接在 10:00–11:00 之后。

**设计。** 确认时区和含开始、不含结束的区间语义。约定创建成功返回 201 及预约号，冲突返回 409 及稳定错误码。选取能保证重叠区间互斥的数据库约束，或说明事务隔离、并发写入和重试如何共同保证该规则。单独对“会议室＋开始时间”设唯一约束会漏掉起始时刻不同的重叠区间。

**拆工。** T0 由主 Agent 确认契约。T1 实现存储和服务，T2 按契约实现页面反馈，T3 根据 AC 独立编写验收用例。三项均依赖 T0，可在各自范围并行。T4 等待前三项，集成后通过两个独立客户端发起请求，同时核对两次响应和最终数据。记录实际结果后再给出验收结论。
